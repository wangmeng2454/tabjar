## 2. 决策记录（ADR）

### ADR-01｜采用收纳式而非挂起式
- **背景**：竞品有三类路线（收纳/挂起/看板）。
- **决策**：以**收纳式**为主（记录 URL 并关闭标签）。
- **理由**：内存收益最大、心智最简单、开发成本最低、与 OneTab 用户习惯一致。
- **代价**：恢复丢滚动/表单（接受，二期再评估）。

### ADR-02｜本地优先，一期不做云同步
- **决策**：数据仅存本地，无账号、无上传。
- **理由**：隐私优先、合规简单、零成本；用导出功能兜底迁移。
- **代价**：换机需手动导出导入（可接受）。

### ADR-03｜技术栈选用 TS + Vite + CRXJS，UI 用原生 DOM
- **决策**：TypeScript 强类型；Vite+CRXJS 负责构建；**不引入前端框架**。
- **理由**：界面简单，框架会增大包体、拖慢启动；原生 DOM 更利于「轻量」定位。
- **代价**：复杂交互（如拖拽）需手写（二期再评估）。

### ADR-04｜权限最小化
- **决策**：仅申请 `tabs`、`storage`、`contextMenus`；不申请 host 权限。
- **理由**：权限即信任；安装提示越少越易装、越易审核过。

### ADR-05｜数据模型可演进，向后兼容
- **决策**：入库前统一 `sanitizeGroup` 清洗 + 默认值补齐。
- **理由**：旧版本数据可平滑升级；未来新增字段不破坏兼容。

### ADR-06｜action 不设 default_popup
- **决策**：点击图标直接触发收纳（`action.onClicked`），不弹出小窗。
- **理由**：OneTab 的核心交互是「一点即收纳」，popup 会打断这个心智。
- **约束**：manifest 中 `action` 绝不能加 `default_popup`。

### ADR-07｜先落盘后关标签（数据安全铁律）
- **决策**：收纳时先写 undo + groups，再关闭标签。
- **理由**：任何中途异常都不能导致数据永久丢失。
- **约束**：所有涉及「关标签」的代码必须遵守此顺序。

### ADR-08｜产品命名：OneTab → TabJar（标签罐）
- **背景**：原暂定名 "OneTab" 与知名扩展 OneTab 同名。经查，OneTab 官网明确声明
  "OneTab is a trademark of OneTab Ltd."，该公司有 WIPO 商标/域名维权先例（350 万周活）；
  华为应用商店规范亦要求「应用名称唯一、不得盗用知名应用名称」，违者可导致开发者账号被封。
- **决策**：正式命名为 **TabJar（标签罐）**，彻底避开任何 "OneTab" 相关名称
  （含 "Better OneTab" 等社区分叉名，同样存在商标风险）。
- **备选排除**：TabNest / TabHarbor / TabShelf / Tab Stash / Tab Vault 均已被同类扩展占用。
- **代价**：全项目重命名（清单 `name`、`package.json`、代码文案、文档标题、目录名）。
- **命名原则**：避开现有商标、避开 "One" 前缀、不与在架扩展撞名、中英双语可读。

### ADR-09｜分组折叠状态独立存 `collapsed` 键，不混入 `groups` 与 `settings`
- **背景**：F-3.8 需要「折叠/展开分组」并持久化。可选落点有三处：① 写进 `TabGroup`（如 `group.collapsed`）；
  ② 塞进 `Settings`；③ 独立存储键。涉及 `docs/05` 数据契约与 `docs/04` 的迁移策略，需先定。
- **决策**：新增 `chrome.storage.local` 键 **`collapsed: string[]`**（元素为 `group.id`），
  由 `storage.ts` 的 `loadCollapsed()` / `saveCollapsed()` 读写；**不写进 `TabGroup`，也不混入 `Settings`**。
- **理由**：
  1. **数据与视图分离**：`TabGroup` 是用户数据，会**导出成 JSON**；折叠是界面偏好，若混入会让导出文件带上本地视图状态、污染 `docs/05` 的数据契约，并让"往返一致"（TK-907）更难判定。
  2. **避免污染设置迁移**：`loadSettings()` 是逐字段白名单校验，塞入一个「按组 id 的集合」会显著加复杂度。
  3. **生命周期不同**：分组会随收纳/删除而增删，折叠状态是"跟随 id 的浮标"，独立存放才好按 id 做孤儿清理。
- **代价**：需额外维护一把键，并在 `persist()` 中统一 prune 掉已不存在分组 id（见 TK-212 规格第 9 条）；
  `onStorageChanged` 的"无变化则 return"判断需把 collapsed 一并纳入比对。
- **约束**：折叠状态改变时**不得** `clearSelection()`（只有 `groups` 变化才清），否则用户勾选会被无谓打断。
