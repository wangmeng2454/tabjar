## 1. 数据模型总览

```
chrome.storage.local
├── groups   : TabGroup[]        // 所有已收纳分组（核心数据）
├── settings : Settings          // 用户设置
└── undo     : UndoSnapshot|null // 「撤销收纳」快照（只保留最近一次）
```

---

## 2. 类型定义（对应 `src/types.ts`）

### 2.1 TabRecord —— 单条标签页记录
```ts
interface TabRecord {
  url: string            // 页面地址（仅 http/https/file）
  title: string          // 页面标题（空则用 url 兜底）
  favIconUrl?: string    // 图标地址（可选：页面未加载完时浏览器可能不给）
}
```

### 2.2 TabGroup —— 一次收纳产生的分组
```ts
interface TabGroup {
  id: string             // crypto.randomUUID() 唯一标识
  name: string           // 分组名（默认「10月7日 22:30」，可重命名）
  createdAt: number      // 收纳时间戳（Date.now()，毫秒）
  starred: boolean       // 是否星标（星标分组置顶）
  tabs: TabRecord[]      // 组内所有标签页
}
```

### 2.3 Settings —— 用户设置
```ts
type ThemeName = 'auto' | 'light' | 'dark'

interface Settings {
  theme: ThemeName        // 主题；auto 跟随系统
  dedupe: boolean         // 收纳时跳过列表中已存在的网址
  excludePinned: boolean  // 收纳时忽略固定标签页
  openInNewWindow: boolean// 恢复整组是否新开窗口
}

const DEFAULT_SETTINGS: Settings = {
  theme: 'auto',
  dedupe: true,
  excludePinned: true,
  openInNewWindow: false,
}
```

### 2.4 UndoSnapshot —— 撤销快照
```ts
interface UndoSnapshot {
  group: TabGroup        // 刚收纳的那一组
  windowId: number | null// 原窗口 id；窗口已关则为 null（退化为当前窗口）
}
```

## 3. 存储键约定

| 键 | 类型 | 说明 | 无值时默认 |
|---|---|---|---|
| `groups` | `TabGroup[]` | 分组列表 | `[]` |
| `settings` | `Settings` | 设置 | `DEFAULT_SETTINGS` |
| `undo` | `UndoSnapshot \| null` | 撤销快照 | `null` |

> 统一在 `src/storage.ts` 集中读写，键名以常量形式定义，**禁止散落各处硬编码**。

## 4. 存储 API 封装

| 函数 | 签名 | 说明 |
|---|---|---|
| `loadGroups` | `() => Promise<TabGroup[]>` | 读分组 + 逐条清洗迁移 |
| `saveGroups` | `(g: TabGroup[]) => Promise<void>` | 整体覆盖写入 |
| `loadSettings` | `() => Promise<Settings>` | 读设置 + 缺省补齐 |

| `loadUndo` | `() => Promise<UndoSnapshot \| null>` | 读快照 |

| `clearUndo` | `() => Promise<void>` | 清空快照（语义化封装） |

## 5. 数据迁移与校验

**问题**：`chrome.storage` 读出的数据在类型上**不可信**——可能来自旧版本、可能被用户手改、可能是空。

**方案**：入库前一律经 `sanitizeGroup` 洗一遍。

```ts
function sanitizeGroup(raw: unknown, index: number): TabGroup
```

迁移规则：
| 情况 | 处理 |
|---|---|
| 非对象 / null | 按 `{}` 处理 |
| 缺 `id` | 生成 `legacy-<时间戳>-<下标>` |
| 缺 `name`（旧版 1.0.0 无此字段） | 用 `formatGroupName(createdAt)` 补 |
| 缺 `starred`（旧版无此字段） | 默认 `false` |
| `tabs` 非数组 | 视为 `[]` |
| 单条 `url` 为空 | 过滤掉 |
| `favIconUrl` 不存在 | 不写入该字段（保持可选语义） |

> 收益：未来新增字段时，老用户数据可**平滑升级**，不会因缺字段崩溃。

## 6. 数据一致性规则

1. **先落盘、后关标签**（背景见技术方案 §3.1），这是数据不丢的根本保证。
2. **组不空置**：任何删除操作后若某组 `tabs.length === 0`，自动移除该组。
3. **选中项清理**：删除组时要同步清理该组相关的批量选中键，避免悬空引用。
4. **排序不变式**：星标分组恒在最前；同级按 `createdAt` 新→旧。
5. **undo 唯一**：只保留最近一次收纳的快照，新的收纳覆盖旧的。

## 7. 容量与限额

| 项 | 说明 |
|---|---|
| `chrome.storage.local` 默认上限 | 约 10 MB（Chrome 系） |
| 单条记录体积 | ~200–500 字节（URL+标题+图标地址） |
| 可存条数估算 | 万级（10MB / 400B ≈ 2.5 万条） |
| 超限风险 | 图标 URL 很长或标题极长时增多；**建议二期按需申请 `unlimitedStorage`** |

> MVP 阶段默认容量足够；若监测到增长异常，二期加入 `unlimitedStorage` 权限或数据分片。

## 8. 导入 / 导出格式

### 8.1 导出
| 格式 | MIME | 用途 |
|---|---|---|
| JSON | `application/json` | 结构化备份、跨设备迁移、程序处理 |
| HTML | `text/html` | 可被浏览器「导入书签」直接识别 |
| TXT | `text/plain` | 纯链接清单，人类可读 |

**JSON 结构**（与内部模型对齐）：
```json
{
  "version": "2.0.0",
  "exportedAt": 1759843200000,
  "groups": [
    {
      "id": "uuid",
      "name": "10月7日 22:30",
      "createdAt": 1759843200000,
      "starred": false,
      "tabs": [
        { "url": "https://example.com", "title": "示例" }
      ]
    }
  ]
}
```

### 8.2 导入
- **JSON**：校验 `groups` 数组 → 逐条走 `sanitizeGroup`。
- **纯文本**：正则提取所有 `http(s)://...` 链接，生成一个新分组。
- 导入结果**插到列表最前**，不覆盖现有数据。

## 9. 未来演进（不破坏兼容）

| 演进 | 兼容策略 |
|---|---|
| 新增设置项 | `loadSettings` 已用默认值补齐 → 老数据无损 |
| 新增分组字段（如 `note`/`color`） | `sanitizeGroup` 加默认值即可 |
| 加入「历史快照」 | 新增独立键 `snapshots`，不动物模型 |
| 加入云同步 | 复用 JSON 序列化格式，加密上传 |
| 更换存储（IndexedDB） | 保持 `storage.ts` 接口不变，内部替换实现 |
