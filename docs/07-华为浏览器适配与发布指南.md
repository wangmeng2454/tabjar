## 1. 华为浏览器扩展基础认知

| 项目 | 说明 |
|---|---|
| 内核 | **Chromium（Blink）**，与 Chrome 同源 |
| 扩展标准 | 支持 **Manifest V3**；MV2 已淘汰 |
| 平台 | PC 版（Windows 10+ 64 位 / 鸿蒙电脑版）；**移动端不支持扩展** |
| 最低版本 | PC 版建议 ≥ 11.0.5.x（旧版本对扩展支持不完整） |
| 管理入口 | 地址栏 `chrome://extensions` 或 菜单 → 管理扩展程序 |
| API 兼容 | 绝大多数 `chrome.*` API 与 Chrome 行为一致 |

**结论**：技术上**无需为华为浏览器单独写代码**，一份 MV3 扩展即可跨华为/Chrome/Edge 运行。真正的差异集中在**安装方式、签名校验、上架合规**三处。

## 2. 已知差异与适配要点

### 2.1 安装入口默认隐藏
华为浏览器默认隐藏扩展安装入口，需**开启「开发者模式」**才能「加载已解压的扩展程序」。
→ 对用户而言是使用门槛，需在文档/引导中说明（我们提供 README 步骤）。

### 2.2 CRX 签名 / CSP 校验更严格
从三方下载的 `.crx` 直接拖入可能报：
- 「无法加载此扩展程序」
- `Manifest file missing or invalid` / `Invalid value for 'key'`

**常见解决**：把 `.crx` 改名为 `.zip` 解压 → 修改 `manifest.json` → 以「加载已解压」方式加载。

### 2.3 `wasm-unsafe-eval` 导致加载失败
若扩展 CSP 含 `'wasm-unsafe-eval'`，部分华为版本会校验失败。需从 `content_security_policy.extension_pages` 中**移除该指令**。

```jsonc
// 修改前（可能失败）
"content_security_policy": {
  "extension_pages": "script-src 'self' 'wasm-unsafe-eval'; object-src 'self'"
}
// 修改后（推荐）
"content_security_policy": {
  "extension_pages": "script-src 'self'; object-src 'self'"
}
```
> 本项目当前**未使用 wasm**，且构建产物 CSP 默认不含该指令，天然规避此问题 —— 这也是「纯 MV3 + 无框架 + 无 wasm」选型的额外收益。

### 2.4 API 行为细微差异
- `chrome.runtime.sendMessage` 在个别华为版本存在兼容性波动 —— 本项目**不依赖常驻消息传递**（用 storage 作为唯一数据源），天然规避。
- `chrome.sidePanel` 等较新 API 需实测确认支持度（二期使用前必须验证）。

### 2.5 内部页前缀
华为浏览器内部页可能使用自有前缀。本项目的 `isCollectibleUrl` 只放行 `http/https/file`，其余一律跳过，**天然兼容任何前缀**。

## 3. 开发调试流程（华为浏览器 PC 版）

```
1. npm run build                # 生成 dist/
2. 打开华为浏览器 → chrome://extensions（或 菜单→管理扩展程序）
3. 右上角打开「开发者模式」
4. 点「加载已解压的扩展程序」→ 选择 dist/ 目录
5. 修改代码后：npm run build → 回扩展页点「刷新」图标
```

**调试入口**
| 目标 | 方式 |
|---|---|
| Service Worker | 扩展管理页点「Service Worker」链接开 DevTools |
| 列表页 | 直接在列表页按 F12 |
| 存储数据 | DevTools → Application → Storage（或 `chrome.storage` 调试） |

> 本扩展无 content script、无 popup，故无需「审查弹窗/注入脚本」步骤。

## 4. 打包与分发

### 4.1 方式一：开发者模式加载（开发/自用）
直接加载 `dist/` 目录，最简单，适合开发与内部试用。

### 4.2 方式二：`.crx` 打包（小范围分发）
```powershell
# 用 Chrome 打包（生成 tabjar.crx + tabjar.pem，pem 务必妥善保管）
chrome.exe --pack-extension="D:\workplace\tabjar\dist"
```
- 分发给用户时，用户可能需按 §2.2/§2.3 处理后加载。
- **`key` 与 `.pem`**：如需固定扩展 ID，在 manifest 中加入 `key`（公钥 Base64）。**私钥 `.pem` 绝不入库、绝不外泄。**

### 4.3 方式三：华为扩展中心上架（正式发布）
1. 注册 **华为开发者账号** 并完成**实名认证**（个人/企业）。
2. 准备上架材料：
   - 扩展包（符合 MV3 规范）
   - 512×512 图标、多张截图（至少 3 张）
   - 中文名称、简介、详细描述（含功能与权限说明）
   - **隐私政策 URL**（说明：本扩展不收集任何数据）
   - 用户协议 URL
3. 提交 → 审核 → 发布。
4. 后续更新走同渠道。

## 5. 上架合规检查清单

依据华为应用/扩展上架规范，逐条自检：

| 检查项 | 本项目情况 |
|---|---|
| 不含病毒/恶意代码 | ✅ 纯本地逻辑，无远端代码 |
| 无通知栏/弹窗广告、无积分墙 | ✅ 零广告 |
| 权限最小化、无不相关权限 | ✅ 仅 tabs/storage/contextMenus |
| 权限用途说明清晰 | ✅ 在描述与本文档中说明 |
| 不开机自启、不后台常驻偷跑 | ✅ Service Worker 按需唤醒 |
| 不影响设备性能 | ✅ 轻量、无常驻 |
| 适配深色模式 | ✅ 已适配（浅/深/跟随系统） |
| 内容合法合规（无涉黄暴政等） | ✅ 工具类，无用户生成内容 |
| 名称不含广义归纳类词 | ✅ 使用独立名称 |
| 提供隐私政策与联系方式 | ⚠️ **待补**：需准备隐私政策页 |
| 应用信息与实际一致 | ⚠️ 上架时填写需与包内一致 |

## 6. 隐私与数据合规说明（可直接用于隐私政策）

> 本扩展**不收集、不上传、不共享任何用户数据**。
> · 所有标签页信息与设置仅保存在用户设备的浏览器本地存储中。
> · 扩展不访问浏览历史、书签、Cookie，不注入任何网页。
> · 扩展不发起任何网络请求，不含任何统计/遥测代码。
> · 用户可随时导出或清空全部数据。
> · 卸载扩展即删除本地数据。

## 7. 常见问题（FAQ）

| 问题 | 原因 / 解决 |
|---|---|
| 加载报「Manifest 无效」 | 确认加载的是 `dist/`（含构建后的 manifest.json），而非 `src/` |
| CRX 拖入失败 | 用开发者模式「加载已解压」；必要时按 §2.2 处理 |
| 点击图标无反应 | 检查 manifest 的 `action` **未设置 `default_popup`** |
| 图标不显示徽标数字 | 需 `chrome.action` 权限可用；确认已收纳数据 |
| 收纳后没关标签 | 检查是否为固定标签页、扩展页或非 http(s) 页面 |
| 快捷键无效 | 快捷键是「建议值」，可能与其他冲突，到 `chrome://extensions/shortcuts` 修改 |
| 换电脑数据没了 | 数据在本地，需**导出 JSON** 再在新设备导入 |
