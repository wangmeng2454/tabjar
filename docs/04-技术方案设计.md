## 1. 技术选型

| 层面 | 选择 | 理由 |
|---|---|---|
| 扩展标准 | **Manifest V3** | V2 已淘汰；MV3 是 Chrome/Edge/华为当前标准 |
| 语言 | **TypeScript** | 强类型，数据模型可编译期校验，防低空错误 |
| 构建 | **Vite 5** | 快、生态成熟、天然支持 ESM |
| 扩展打包 | **@crxjs/vite-plugin** | 自动生成 manifest、处理 SW 与 HMR |
| 存储 | **chrome.storage.local** | 扩展标准本地存储，异步、容量大于 localStorage |
| UI | **原生 DOM + CSS**（无框架） | 列表页简单，零框架可让包体最小、启动最快 |
| 图标 | PNG（16/32/48/128） | 浏览器要求的标准尺寸 |

**为什么不用 React/Vue？** 列表页是一个「读数据 → 渲染列表 → 事件操作 → 落盘 → 重渲染」的简单闭环，引入框架只会增大包体、拖慢启动，收益有限。原生 DOM 足够，且更利于保持「轻量」定位。

### 2.2 模块职责

| 文件 | 职责 | 是否碰 chrome.* | 是否碰 DOM |
|---|---|---|---|
| `manifest.config.ts` | 清单定义（权限、入口、快捷键、右键） | — | — |
| `src/types.ts` | 数据模型 interface + 默认值常量 | ✗ | ✗ |
| `src/utils.ts` | 纯函数（时间/域名/去重/估算/格式化） | ✗ | ✗ |
| `src/storage.ts` | `chrome.storage` 读写 + 数据迁移 | ✓ | ✗ |
| `src/serialize.ts` | JSON/HTML/TXT 导出与解析 | ✗ | ✗ |
| `src/background.ts` | Service Worker：采集、落盘、关标签、菜单、快捷键 | ✓ | ✗ |
| `src/dom.ts` | DOM 小工具（`$`、`el`、下载） | ✗ | ✓ |
| `src/tabs/tabs.ts` | 列表页逻辑 | ✓ | ✓ |

> 分层原则：**纯逻辑（utils/serialize）与平台耦合（storage/background）分离**，纯函数最易测试、最易复用。

## 3. 关键流程

### 3.1 收纳流程（核心，保证不丢数据）

```
用户点击图标
   ↓
background: action.onClicked → collectWindow(windowId)
   ↓
chrome.tabs.query({windowId})  ← 取得窗口全部标签
   ↓ 过滤：去掉 扩展页 / chrome-extension:// / 非 http(s)/file / 固定页(按设置)
   ↓
采集为 TabRecord[] → 按设置去重（列表已存在 / 批次内重复）
   ↓
┌────────────────────────────── 关键顺序 ──────────────────────────────┐
│ 1. saveUndo(快照)        ← 先写撤销快照                                 │
│ 2. saveGroups([新分组,...]) ← 再写分组（插到第一个非星标位置）           │
│ 3. openListPage()        ← 打开/聚焦汇总页                              │
│ 4. chrome.tabs.remove()  ← 最后才关闭标签                               │
└──────────────────────────────────────────────────────────────────────┘
   ↓
updateBadge()  更新徽标数字
```

> ⚠️ **铁律**：任何「先关标签、后存数据」的写法都可能在异常时永久丢数据。必须先落盘。

### 3.2 恢复流程
- **单条**：`chrome.tabs.create({url})` → 从分组 `splice` 掉该条 → 落盘（组空了则删组）。
- **整组**：按设置 `openInNewWindow` 决定 `windows.create({url:[...]})` 还是逐个 `tabs.create`。
- **全部**：`flatMap` 所有 tabs 后一次性打开，清空分组。

### 3.3 撤销流程
- 收纳时写入 `undo = { group, windowId }`。
- 用户点「撤销」→ 用快照把标签放回**原窗口**（`windowId` 用 `WINDOW_ID_CURRENT` 兜底）→ 删除该分组 → 清空 undo。

### 3.4 打开/聚焦列表页
- 用 `chrome.tabs.query({})` 全量取回后**按字符串比对 URL**定位列表页（比用 `query({url})` 匹配模式更可靠）→ 存在则 `update({active})+windows.update({focused})`，否则 `create`。

## 4. Manifest V3 权限设计

```ts
permissions: ['tabs', 'storage', 'contextMenus']
action: { default_icon, default_title }   // 不设 default_popup！
background: { service_worker: 'src/background.ts', type: 'module' }
commands: { collect-all, open-list }
```

**关键点**
- `action` **不能设 `default_popup`**，否则点击只弹小窗，`action.onClicked` 永不触发。
- `host_permissions` 留空：本扩展**不注入任何网页**，无需站点权限。
- 不申请 `history`/`bookmarks`/`webRequest`/`<all_urls>`：权限即信任。

## 5. 安全性设计

| 风险 | 对策 |
|---|---|
| 恶意 URL 存储 | 只允许 `http/https/file`，过滤 `javascript:` 等 |
| XSS（列表页渲染用户内容） | 用 `textContent` / `el()` 创建节点，**不拼接 innerHTML** |
| 图标加载失败 | `img.onerror` 回退为字母占位块 |
| 存储数据被篡改/旧版本 | 入库前 `sanitizeGroup` 强校验 + 字段补齐 |
| 数据外泄 | 无网络请求、无遥测；导出仅用户主动触发 |
| 权限滥用 | 最小权限集；无 host 权限 |

## 6. 性能设计

- **去重**：用 `Set`（O(1)）而非数组 `indexOf`（O(n)），大批量时差异显著。
- **DOM 渲染**：先算「每组的可见下标」，再统一渲染；搜索时只渲染命中项。
- **批量删除**：选中下标**从大到小**排序后 `splice`，避免下标错位。
- **徽标更新**：仅在数据变更后调用一次。
- **Service Worker**：不常驻，状态全部落盘，每次唤醒重算徽标。

## 7. 兼容性设计

| 关注点 | 说明 |
|---|---|
| MV3 API 差异 | 华为浏览器 Chromium 内核，绝大多数 `chrome.*` API 与 Chrome 一致 |
| `wasm-unsafe-eval` | 华为加载第三方 CRX 时可能因 CSP 校验失败，需去掉该指令（见适配指南） |
| `chrome.runtime.getURL` | 在华为环境建议路径用相对/标准写法，避免特殊行为 |
| 内部页前缀 | 过滤 `chrome://`、`chrome-extension://`；对其它前缀用正则兜底 |
| 快捷键冲突 | `suggested_key` 仅建议值，用户可改；避免占用浏览器常用键 |

## 8. 构建与开发

```powershell
npm install        # 安装依赖
npm run build      # 构建到 dist/
npm run watch      # 监听改动自动重建
npm run typecheck  # 仅类型检查（tsc --noEmit）
```

**构建要点**：列表页 `src/tabs/tabs.html` 未被 manifest 引用，必须在 `vite.config.ts` 的 `rollupOptions.input` 显式声明为入口，否则不会被 Vite 打包。`target: 'es2022'` 因源码使用顶层 `await`。

**目录结构**
```
tabjar/
├── manifest.config.ts     # 清单（TS）
├── vite.config.ts         # 构建配置
├── tsconfig.json

├── src/
│   ├── types.ts           # 数据模型
│   ├── utils.ts           # 纯函数
│   ├── dom.ts             # DOM 工具
│   ├── storage.ts         # 存储封装 + 迁移
```

## 9. 二期技术预研（列备选，不本期实现）

1. **挂起式恢复**：MV3 无直接「挂起」API，可行方案是「恢复时打开一个轻量占位页 + 记录原 URL」，或结合 `tabs.discard`。需单独评估。
2. **自动快照**：用 `chrome.alarms` 定时把当前 groups 存一份带时间戳的备份，实现历史版本。
3. **侧边栏视图**：`chrome.sidePanel`（需核对华为内核支持度）。
4. **可选云同步**：序列化层已就绪，未来接入端到端加密的同步服务即可，不动核心模型。
