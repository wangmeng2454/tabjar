## 1. 项目背景

### 1.1 问题陈述
现代用户习惯「用标签页代替书签」：开几十个标签、不关、下次继续看。结果：
- 浏览器内存暴涨（30 个标签常占 3~8 GB），系统卡顿、风扇狂转。
- 标签栏挤成一排小图标，标题不可辨，找页面靠猜。
- 手动关标签会「弄丢重要页面」，形成「不敢关 → 更卡 → 更不敢关」的恶性循环。

### 1.2 华为浏览器现状
- 华为浏览器（PC 版）基于 **Chromium 内核**，支持 **Manifest V3** 扩展，扩展技术与 Chrome 同源。
- 扩展生态尚在起步：默认隐藏扩展安装入口，需开启「开发者模式」加载，官方扩展中心上架扩展较少。
- 因此：**为其提供一款原生体验好、隐私安全、中文优先的标签收纳扩展**，存在明确空白与机会。

### 1.3 为什么是现在
竞品（OneTab 等）验证了「一键收纳」的刚需（200 万+ 用户），但在**本地化、数据安全、组织能力**上普遍偏弱（详见竞品调研）。

## 2. 产品定位与目标

### 2.1 产品定位
> **一句话**：点一下，把所有标签页收进一个清爽的列表，立刻释放内存；随时一键全部找回。

- 形态：浏览器扩展（Manifest V3），主战场 **华为浏览器 PC 版**，兼容 Chrome / Edge。
- 风格：**极简默认 + 渐进增强**。打开即用，0 学习成本；进阶功能藏在设置里。

### 2.2 产品目标（可度量）
| 目标 | 指标 |
|---|---|
| 核心价值达成 | 收纳 N 个标签后内存显著下降（估算展示「约可释放 X」） |
| 易用性 | 新用户无需教程即可完成「收纳 → 恢复」闭环 |
| 数据安全 | 100% 本地存储，默认零上传；支持导出备份 |
| 稳定性 | 收纳/恢复 100% 不丢数据（先落盘再关标签） |
| 轻量 | 安装包 < 300 KB，空闲内存占用可忽略 |

### 2.3 非目标（一期明确不做）
- ❌ 云同步 / 账号体系（隐私与合规成本高，属于付费竞品领域）。
- ❌ AI 分组 / 摘要（前沿但非刚需，依赖外部能力）。
- ❌ 团队协作 / 工作区共享。
- ❌ 移动端（华为浏览器移动端不支持扩展）。

## 3. 用户画像与场景

### 3.1 目标用户
| 画像 | 特征 | 核心诉求 |
|---|---|---|
| **P1 多任务知识工作者** | 产品/运营/研发/研究员，一天开几十个标签 | 中途保存、下班继续、快速找回 |
| **P2 内存焦虑用户** | 老电脑/笔记本，浏览器一卡就烦 | 一键腾内存、操作零门槛 |
| **P3 资源囤积者** | 习惯「先存着，以后看」 | 不怕关标签、随时找回、不丢失 |

### 3.2 核心用户故事（User Story）
- **US-1**：作为多任务用户，我想**一键收纳当前窗口所有标签**，以便立刻释放内存。
- **US-2**：作为用户，我想**在列表里按标题/网址搜索**，以便快速找到之前存的页面。
- **US-3**：作为用户，我想**恢复单条 / 整组 / 全部标签**，以便继续工作。
- **US-4**：作为用户，我想**给分组改名/星标**，以便区分「工作资料」「待读文章」。
- **US-5**：作为用户，我想**撤销刚才的收纳**，以便误操作后反悔。
- **US-6**：作为用户，我想**导出/导入列表**，以便备份或换设备迁移。
- **US-7**：作为用户，我想**保留某些标签不被收纳**（如固定页/正在播放的音乐），以免误关。
- **US-8**：作为用户，我想**批量选中若干条目**，以便一次性恢复或删除。
- **US-9**：作为用户，我想**从右键菜单直接打开 TabJar 列表**，以便在不收纳任何标签的前提下，随时查看已存的页面。
- **US-10**：作为用户，我想**把某个分组折叠起来**，以便在存了几十组、每组几十条时，先看到全部组名再逐组展开，不被长列表淹没。
- **US-11**：作为用户，我想**导出的 JSON 再导回来时保持原样**（分组数、组名、星标、图标都不变），以便把备份当成真正的备份用。
- **US-12**：作为用户，我想把 **OneTab 导出的「网址 \| 标题」文本**直接粘贴导入并**保留每条的标题**（如「博德之门3 职业大全最终修订版文字版 - 哔哩哔哩」），以便从旧工具无缝迁移，而不是每条都只剩一个域名。

### 3.3 典型使用流程
```
打开一堆标签  →  点工具栏图标 / 快捷键 Ctrl+Shift+E
   → 所有标签收进列表并关闭（弹出汇总页）
   → 需要时：单击条目恢复 / 恢复整组 / 搜索定位
   → 误操作：点「撤销收纳」放回原窗口
```

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| **性能** | 收纳/恢复 300 条 < 2s；列表页渲染 1000 条可流畅滚动 |
| **可靠性** | 先落盘后关标签；Service Worker 被回收后状态不丢 |
| **安全** | 最小权限；不注入网页；不读取浏览历史内容；不发起网络请求 |
| **隐私** | 数据仅存本地；无遥测；导出由用户主动触发 |
| **兼容** | Manifest V3；华为浏览器 PC / Chrome / Edge 通用 |
| **可维护** | TypeScript 强类型；模块化；注释完备 |
| **无障碍** | 关键操作可用键盘；深色模式对比度达标（正文 ≥ 4.5:1） |
| **体积** | 构建产物 < 300 KB（不含图标） |

## 6. 权限需求（MVP 最小集）

| 权限 | 用途 | 必要性 |
|---|---|---|
| `tabs` | 读取标签的 URL/标题/图标，关闭标签 | 必需 |
| `storage` | 本地保存分组与设置 | 必需 |
| `contextMenus` | 右键菜单收纳 | 需要 |
| （不申请）`history` / `bookmarks` / `webRequest` / `<all_urls>` | — | **明确不申请** |

> 原则：**权限即信任**。安装时提示越少，用户越愿意装，审核越容易过。

## 7. 验收标准（Definition of Done）

1. 在华为浏览器 PC 版中，可通过「开发者模式 → 加载已解压扩展」成功加载并运行。
2. **收纳入口齐备**：点击图标 / 快捷键 / 右键菜单三种方式均可完成收纳。
3. **列表页入口齐备**：收纳后自动打开、快捷键 `Ctrl+Shift+Y`、右键菜单「打开 TabJar 列表」均可打开或聚焦列表页。
4. 收纳后列表页正确展示全部条目，内存占用明显下降。
5. 单条/整组/全部恢复、删除、清空、撤销全部工作正常。
6. 搜索、重命名、星标、批量操作、导入导出全部可用。
7. **分组可折叠 / 展开**：折叠后仅保留分组头（组名 + 条数）；折叠状态在刷新/重开列表页后保持；搜索命中该组时自动展开；折叠**不影响**「全选本组」的选中范围。
8. **导出 → 导入可原样还原**：导出含 N 组的 JSON，清空后再导入，分组数、组名、星标、页面图标均保持一致（即 `serialize.ts` 注释所述「JSON 是唯一能原样导回的格式」成立）。
9. 深色/浅色/跟随系统主题切换正确。
10. 关闭浏览器重开，数据仍在（持久化正确）。
11. 无控制台报错；`npm run typecheck` 与 `npm run build` 通过。

## 8. 依赖与约束

- **技术栈**：TypeScript + Vite + @crxjs/vite-plugin（Manifest V3）。
- **浏览器**：Chromium 内核（华为浏览器 PC ≥ 11.0.5.x / Chrome / Edge）。
- **分发**：开发者模式加载或 `.crx` 分发；正式上架需华为开发者账号 + 实名认证（见适配与发布指南）。
- **合规**：遵守华为应用/扩展上架内容规范（无广告、无病毒、权限最小化、隐私说明）。

## 9. 术语表

| 术语 | 含义 |
|---|---|
| 收纳 | 把标签页的 URL/标题记录到列表并关闭标签页 |
| 分组 / Group | 一次收纳产生的一组标签页记录 |
| 徽标 / Badge | 扩展图标上的数字提示 |
| Service Worker | MV3 的后台脚本，非持久、按需唤醒 |
| 挂起 / Suspend | 保留标签位置但卸载页面内存 |
